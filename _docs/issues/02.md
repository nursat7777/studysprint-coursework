## Goal
As a student I can save and maintain coursework without losing valid records.

## Acceptance criteria
### Functional behavior
- [ ] Task schema has unique string id, title, subject, dueDate, priority, notes, completed and createdAt.
- [ ] Create generates a unique stable ID and genuine createdAt timestamp.
- [ ] Trim title and subject before validation and saving.
- [ ] Title accepts 1–120 characters after trimming; rejects blank or 121+.
- [ ] Subject accepts 1–80 characters after trimming; rejects blank or 81+.
- [ ] Notes are optional and accept at most 2000 characters.
- [ ] Priority is exactly low, medium or high; default medium is visible.
- [ ] Due date is an actual local calendar date in YYYY-MM-DD format.
- [ ] Past due dates are accepted as valid assignment dates; impossible dates are rejected.
- [ ] Edit updates the existing ID rather than adding a duplicate.
- [ ] Editing does not unexpectedly change completion or createdAt.
- [ ] Complete marks a task completed; reopen restores it to active.
- [ ] Delete asks confirmation; cancellation leaves all tasks unchanged.
- [ ] Confirmed deletion removes only the selected task.

### Failure and persistence
- [ ] Validation errors are visible near fields and prevent mutation.
- [ ] Saved tasks survive browser refresh.
- [ ] Missing storage initializes an empty state.
- [ ] Malformed stored JSON/schema is handled without application crash.
- [ ] Corrupt storage is reported visibly and not silently presented as valid data.
- [ ] Storage write/quota failure is visible; never falsely claim successful persistence.
- [ ] A failed storage write preserves prior saved records.
- [ ] Task text is rendered safely without raw HTML.

### Verification
- [ ] Automated tests exercise trim/blank/maximum lengths and date validity.
- [ ] Automated tests cover edit identity, completion/reopen and storage validation.
- [ ] Testing Library component integration tests exercise create/edit/delete/complete and persisted reload behavior.

### Definition of Done
- [ ] Changes committed with genuine history; actual issue linked when available.
- [ ] Independent QA records acceptance evidence; failures fixed before closure.

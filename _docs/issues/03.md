## Goal
As a student I can identify urgent coursework and find the right task.

## Acceptance criteria
### Dashboard
- [ ] Total count includes all tasks.
- [ ] Completed count includes only completed tasks.
- [ ] Overdue count includes only active tasks with date before local today.
- [ ] Due-today count includes active tasks due on the local current date.
- [ ] Counts remain unchanged when list search/filter changes.
- [ ] Completed past-date tasks are excluded from urgency counts.

### Finding tasks
- [ ] Search matches title, subject and notes case-insensitively.
- [ ] Empty search restores all otherwise matching tasks.
- [ ] Status filter supports all, active and completed.
- [ ] Priority filter supports all, low, medium and high.
- [ ] Search and both filters combine rather than overwrite each other.
- [ ] Due-date sort orders earlier dates first.
- [ ] Priority sort orders high before medium before low.
- [ ] Equal sort keys produce deterministic ordering.
- [ ] Sorting preserves the underlying records and IDs.
- [ ] Filtered no-results state explains how to adjust filters.

### Accessibility and layout
- [ ] Empty task state provides a clear create action.
- [ ] Every form/filter input has a persistent associated label.
- [ ] Buttons use native keyboard activation and visible focus.
- [ ] Urgency and priority have text labels in addition to color.
- [ ] Responsive CSS defines stacked phone layout, min-width constraints and wrapping; actual browser overflow verification remains unverified.
- [ ] Desktop CSS defines readable assignment panels; timer-panel integration is delivered in follow-up draft 04.
- [ ] CSS wraps long titles/notes and preserves native controls in DOM; actual visual clipping verification remains unverified.

### Verification
- [ ] Unit tests cover combined search/filter/sort and date counts.
- [ ] Inspect responsive CSS/source and DOM structure; record actual browser viewport inspection as unavailable unless executed.
- [ ] DOM integration verifies associated labels and keyboard-operable native controls; visual focus/viewport inspection remains an explicit external limitation.

### Definition of Done
- [ ] Changes committed with genuine history; actual issue linked when available.
- [ ] Independent QA records acceptance evidence; failures fixed before closure.

## Out of scope
Charts and notifications. Timer-panel integration belongs to follow-up draft 04 (`_docs/issues/04.md`). Actual browser overflow, clipping and visual readability checks are unverified external inspection requirements; source/DOM verification does not certify their outcome.
